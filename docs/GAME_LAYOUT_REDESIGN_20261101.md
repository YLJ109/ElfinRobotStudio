## 导航与边界

左侧九项：控制、点位、程序、AI、视觉、娱乐、互动、场景、系统。娱乐页含五种棋；互动含跟随、追踪、绘制、写字；场景含场景物体、分拣。简洁/专业只改变显示，不改变执行条件。

手掌与绘制范围保持用户已确认值。本轮不扩展真机、相机或IO操作；棋类仿真不代表现场工具、TCP或安全资格。

基座约定：前方为-X，正面观察者的左方为+Y；列轴[0,-1,0]，行轴[-1,0,0]。两种象棋棋盘中心[-500,0,180]mm，其余[-500,260,180]mm；供子盘[-500,-260,160]mm，两种象棋提子盘[-480,-420,160]mm。详细尺寸以接口 `physical.layout` 为准，前端不再猜测位置。

棋盘、托盘、边沿与棋子为真实仿真实物并参与碰撞。三维按同组实体位置显示，持件跟随同一机械臂插值矩阵；不能用显示层飞行动画冒充真实取放，不能整体排除棋子碰撞。国际象棋模型及许可见 `web/public/models/games/`。

真实Robotiq模型、运动学、开合与接触几何同源；夹取按棋子宽度开口，避免密集棋阵中全开扫到邻子。双吸盘使用完整板梁与两只杯，有限朝向候选必须包含未工作杯及手腕检查，不靠删除实体工具躲碰撞。照片参考连接段40mm、吸盘30mm只属仿真参考，不是现场标定。

## 操作与响应

- 落子棋先选位置，再点同一位置确认；象棋先选棋子，再选目标。误点不提交。
- 保留开始/终止、暂停/继续。每局先到自己的等待位，回合后返回；吃子先回收、易位分别搬王车，双方棋子都由机械臂完成。
- 用户确认后立即提交；无人工思考倒计时，AI计算有时间/节点预算，状态帧到达立即接下一步。动作仍按用户棋子→电脑棋子串行，计算毫秒数不等于机械运动完成时间。
- 全程沿用顶栏速度，不写入默认8%或15%。
- 点击、选择、落子、开始/结束和切换棋种均不自动改变视角。只有手动操作相机或“对准棋盘”按钮可以对准。
- 2D O/X使用青色圆环和金色圆角叉；SVG焦点不绘制浏览器默认大圆。棋盘贴图避免与支撑顶面重合闪烁。
- 三维底部“清除轨迹”右侧提供“清空场景”，复用场景API，成功后同步清2D/3D及旧会话；保留机器人、围栏、视角和已保存现场文件，任务未停止时不半清空。

## 状态与失败

2D规则只有后端一份；局面、场景和执行会话绑定。旧请求、切页后回复或终止后的结果不能重启任务。暂停覆盖执行中和等待用户阶段，暂停时间不计入正常动作超时。

加载旧局只读状态，不自动重放。失败/终止优先显示实际放下的棋子与未完成状态，不能把未放下的棋子记为成功；失败后禁止继续旧动作，需终止或重新开始。重开前确认当前机械臂任务已经退出。

## 性能顺序

已修：225子同步时每颗子递归更新整棵对象树，改为每次同步共用逆矩阵；离线CPU前后对比与完整坐标检查见 `project.json` 对应证据。未据此宣称GPU帧率或相机检测达到目标。

待实施的相机顺序：共享预热/启动单次模型加载→原始采集与JPEG预览解耦→复用连接推送最新检测结果。先测采集、编码、复制、进程传输、推理、浏览器收到与实际呈现的耗时/帧龄，再选优化；保留队列有界和旧结果失效。

后续三维先做同场景CPU/GPU与绘制调用测量，再决定同材质棋子实例化或复用现有自适应DPR。不得为提高显示流畅度改顶栏运动速度、自动换视角或降低真实状态准确性。
