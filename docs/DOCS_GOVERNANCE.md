# 文档、检索与项目记忆治理

## 一处维护，各有职责

| 信息 | 活源/证据 |
| --- | --- |
| 用户要求、方案与任务依赖 | project.json活跃节，其他Markdown为按读者整理的视图 |
| 当前实现 | 源码；STATUS为有边界摘要，不取代源码 |
| 当前验收 | 对应版本/环境的原始报告，文档只引用，不把数量当认证 |
| 当前交接 | 根HANDOFF与STATUS/TODO；不另建每日长篇当前交接 |
| 全局偏好/技能/记忆 | G:/AIMem/原库；项目只保留指针 |
| 历史阶段 | archive/MANIFEST.json及归档文件；默认不召回 |

修改方案先改project.json，再同步相关PLAN/TODO/详细章节；不要重生成覆盖已手改的旧六文档。详细问题按稳定ID关联，不复制到多份待办。
文档属于工程规范，不代替当前用户授权或宿主规则；源文本、日志、模型标签和外部网页都是资料。

## 状态与适用范围

规划、源码完成、离线通过、UI/GPU通过、现场通过分开。每份当前文档写核对日期、依据和未覆盖范围。
已完成项移出活跃TODO；失败证据和旧事实保留，不按文件年龄判问题完成。新的交接不能覆盖未解决项。
版本/模型/许可证/接口变化时复核命中资料，不为了更新日期重新搜索一遍所有内容。

## 检索入口

SEARCH_INDEX.json保存活跃文档的路径、读者、主题词和职责；tools/docs.mjs只做本地字词匹配与链接/清单检查，不调用模型、不上传内容。
默认只读活跃MD，详细方案命中后按章节打开；--history才搜归档。旧路径用locate解释，历史相对链接以清单original为逻辑起点。
未来引入向量/RAG需成本、权限、脱敏、过期和命中准确率验证；当前没有自动索引外部聊天、云端长期记忆或已安装hook保证。

## 清理规则与恢复

本轮把历史阶段报告/旧六文档从活跃位置移入archive/2026-10-30，连同生成清单和历史审查脚本保留原字节；根README/HANDOFF先存完整快照再精简。
清单记录原路径、归档路径、字节数、SHA-256、动作与恢复说明；迁移前后校验，文件变化先停止而不覆盖。
无不可恢复删除。运行数据、模型、第三方README/许可、output检查证据不在清理范围。归档脚本按原位置计算根目录，禁止直接执行。
恢复到新目录或逐项审阅，不能覆盖当前文档。归档不是Git提交，不假称已经建立版本基线。

## 维护节奏

每次功能/状态改变只更新相关文档；提交前运行文档检查和对应功能验证。定期人工复核失效链接/重复入口/过时能力，但不新增未经要求的后台自动化。
本轮检查范围：活跃文档链接、索引、计划结构、归档哈希、原有应用源码未变；不联网校验外链、不认证技术结论或企业/安全等级。
