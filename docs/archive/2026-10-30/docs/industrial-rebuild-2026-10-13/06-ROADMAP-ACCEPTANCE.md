# 06 实施、测试、验收与交付计划

## 1. 实施原则

先建立可回退基线，再重建控制契约与领域边界，随后迁移UI、工具、轨迹和程序。新旧界面可以并存；设备写入网关不能同时由新旧系统占用。以垂直业务链验收，避免只按文件数宣布完成。

M0–M5 可在当前无真机环境开展；M6 需要实际机器人、工具与工位。M7 是按场景扩展和持续升级。每个阶段输出运行证据及未完成清单；“规划完成”与“功能实现”分别记录。

## 4. 现有验证入口与新门禁

现有入口（由项目根执行；后端综合脚本在临时副本隔离）：

```powershell
.\.venv\Scripts\python.exe tools/run_offline_checks.py
.\.venv\Scripts\python.exe tools/run_offline_checks.py check_cartesian.py check_execution.py check_features.py
```

前端构建（工作目录 `sim/web`）：

```powershell
npm ci
npm run build
```

浏览器专项 `tools/check_cartesian_ui.mjs` 必须先确认其指向隔离后端、禁止真实连接与原始data；不能直接假设当前8710运行端口可以用于测试。`dom_audit.mjs`、`security_check.py`等原脚本先做隔离审查再纳入新门禁。

拟建统一命令（尚不存在，不是可立即执行命令）：

```powershell
.\scripts\check.ps1 -Suite contract -Mode offline
.\scripts\check.ps1 -Suite e2e -Mode offline
.\scripts\check.ps1 -Suite performance -DurationHours 24
.\scripts\doctor.ps1 -ReadOnly
.\scripts\release.ps1 -Version <version> -Offline
```

测试禁止复制`.env`到临时测试报告，不允许外网/机器人socket，不导入运行中的原`World`，数据目录必须位于隔离根。测试用例即使失败也保持隔离，不恢复覆盖用户审计。

## 5. 测试层级

| 层级 | 重点 | 失败处置 |
|---|---|---|
| 领域单测 | 单位/坐标/状态/程序/工具事务 | 任何关键边界失败阻断变更 |
| 属性测试 | 随机FK/IK、finite、角度/姿态边界 | 固定seed保存最小失败样本 |
| 协议契约 | 真实匿名样本+fake控制器+坏报文 | 未覆盖固件标为未资格 |
| 集成 | API/数据库/网关/计算/事件/迁移 | 验证真正边界，不全mock |
| E2E | 输入/残影/程序/换工具/停止/恢复 | DOM与行为证据，截图辅助 |
| 视觉回归 | 主题/窗口/缩放/工具UI/警告 | 固定字体/GPU条件，区分渲染噪声 |
| 安全 | 授权/来源/WS/导入/AI/secret | 实际影响与部署条件记录 |
| 性能 | p50/p95/p99、峰值、内存斜率 | 定位瓶颈，避免只报平均FPS |
| 故障注入 | 延迟/半断线/坏帧/IO/磁盘/崩溃 | 预期locked/unknown与恢复 |
| HIL | 真机回执/路径/到位/停止/工具 | 独立现场档案，软件通过不替代 |
| FAT/SAT | 业务场景和完整交付 | 缺项可见，不把待验证打勾 |

覆盖率是辅助指标，关键领域分支目标≥90%，一般新增模块≥80%；更重要的是所有P0与必选需求100%具有验证用例、结果和证据。测试不得复刻实现而遗漏事件顺序、异步失败和真实边界。

## 6. 必测场景清单

控制：提交前/发送中/回执后/运动中/停稳窗口/IO等待/暂停/重连，各阶段注入停止、断流、回执丢失、错误FSM和重复点击。连续100步只存在一个合法活动执行；停止后旧epoch不再发命令。

运动：零位奇异、已知可达、不可达、关节限位、长距离目标、小步拖动、姿态±180°、多圈、工具偏置、碰撞在采样中间、目标等于当前位置、不同负载下时间参数。

工具：自动ID、无ID手动、控制器仅TCP、错档案、重连换过工具、锁紧未到位、DO接受但未夹到、真空泄漏、未知开口、工具切换断线、参数写了一半、抓取后碰撞、释放掉落。

UI：中文输入法、负数小数、中间字符、保存失败、外部更新冲突、路由重载、页面隐藏、触屏pointercancel、浏览器缩放、极长工具名、1000条消息、无数据、WebGL故障。

数据：空目录、旧版本、非法JSON、重复名称、断电写一半、磁盘满、导出导入、密钥脱敏、备份损坏、回退旧版本、禁止原始data被测试覆盖。

## 7. FAT与SAT分开

FAT软件验收：干净环境安装、离线仿真完整工艺、工具切换、程序编译/执行、故障注入、UI、性能、安全、恢复、证据包。未接真机不能签真机运动/工具项目。

SAT现场验收：机械安装/工具锁紧/电气/气路/保护条件核查 → 只读身份 → 低速空载 → 工具/负载 → 路径与到位 → IO工艺 → 软件停止与真实保护 → 失联/恢复 → 规定工艺节拍/质量 → 长稳。

精度验收使用独立量测或明确厂家方法，分别记录重复定位、绝对位置、姿态、TCP标定、轨迹误差；FK历史对账和IK残差不是实际精度保证。停止距离随速度/负载/姿态测量，不用固定软件数字代替。

现场4h是初步稳定检查，生产验收按工艺规定8/24/72h或更长周期；工具/气源/工件情况必须记录。硬件故障注入根据风险评估选择可控方式，不能为测试盲目拔线/松夹爪导致掉件。

## 8. 数据与源码迁移

1. 清点并备份原data/审计、模型和源码，记录完整摘要；密钥不写进共享清单。
2. 保留现有启动入口，新版本使用独立目录/端口/数据副本，默认禁止真机写入。
3. JSON点位/程序/设置/标定转换事务库，记录schema版本和异常项；原文件保留。
4. 比对实体数量、q/TCP单位、名称、工具/坐标绑定、IO映射；无法推断的绑定标为需确认。
5. 双跑只读对账：同一匿名状态样本进入旧/新计算比较，不双连写控制器。
6. 各域通过后切换对应UI/业务；数据写入口一次只有一个版本。
7. 实机网关切换前停执行、停旧网关、核对设备锁，再由新网关只读确认。
8. 回退同时恢复应用、profile和数据schema；未知现场执行先核对实际状态。

保留审计不会让新测试“还原”覆盖持续写入的原`events.jsonl`。它是现场证据，不是可随意重置的fixture。
