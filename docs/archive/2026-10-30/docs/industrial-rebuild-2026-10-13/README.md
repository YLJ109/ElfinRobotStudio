# HuaYanRobot 全系统工业化重构方案

版本：规划基线 v1.0。日期：2026-10-13。状态：待实施的完整设计，非已完成产品报告。

已落地代码与验证证据见 [实施记录](IMPLEMENTATION-LOG.md)；规划项仍以本文档和需求清单为准。

方案规模：7份Markdown文档、154项需求、20个需求域、62个实施工作包、M0–M7共8个里程碑。正文约4.6万字符。需求编号、任务关联、里程碑、内部链接、编码与代码块结构检查通过，结果见 [文档校验记录](document-validation.json)；这项检查不代表软件或真机验收。

目标是建立可维护、可验证、可交付的工业机器人工作站：从设备识别、示教、工艺编程、预演、真实执行，到故障追溯、运维和验收，形成同一条有证据的闭环。“顶级”用可测指标和现场验收定义，不作为当前能力或认证结论。

本方案覆盖此前请求和本次新增：主题/UI/UX、数字输入、点位只读、AI 标题合并、关节/笛卡尔滑块、残影、逆解、平滑运动、仿真程序、真实控制、控制器程序、全面遥测、性能、网络与机械安全、代码结构、工具爪/吸盘切换、识别与手动回退、创新、数据、测试、部署及交付。

## 本轮核查事实

- 当前根目录未被 Git 识别为仓库；未自动初始化、覆盖或迁移源码。
- 当前前端为 Vue 3 / Pinia / Three.js / Vite，后端为 Python / FastAPI，复用 `huayan_panel/core/protocol.py`。
- 已存在统一执行器、轨迹预检、标定、IO 映射、黑匣子、回放和程序基础；重构需要保留已验证的行为。
- `world.py` 仍承担连接、运动、程序、AI、标定、遥测等多种职责；本次读取的文件超过 1,800 行。
- 当前笛卡尔目标执行仍走关节运动；不能称为 TCP 直线执行。
- 本轮没有连接机器人、发送控制指令、修改实际 IO 或安装末端工具。

## 官方资料核对后的关键结论

1. 官网现售 Elfin-Pro 的型号和参数表不能直接覆盖当前 `E05-1195_Pro`。参数应绑定实际型号、固件、URDF、工具和负载证据。[华沿产品页](https://www.huayan-robotics.com/elfin-pro)
2. 官方 ROS API 将关节目标、笛卡尔目标、直线路径和关节轨迹分开。目标界面必须体现实际执行类型。[华沿官方 API](https://github.com/huayan-robotics/elfin_f_robot/blob/main/docs/API_description_english.md)
3. 本地 V6 通信协议已有 `RunFunc`、`StartScript`、`StopScript`、`PauseScript`、`ContinueScript`、`SwitchScript`、`ReadDefaultScript`。它们是控制器现有程序管理能力的文档证据，不能据此推断任意程序上传、文件格式、固件支持或现场执行已验证。
4. ISO 10218-1:2025 与 ISO 10218-2:2025 分别覆盖工业机器人、工业机器人应用和工作单元；本方案提供工程准备，不宣称认证或满足全部条款。[ISO 10218-1](https://www.iso.org/standard/73933.html)、[ISO 10218-2](https://www.iso.org/standard/73934.html)

## 默认边界

优先单机器人、本地 Windows 工作站、离线可用；真机断开时能完成仿真和工程设计。预留 Linux 运动网关、PLC、视觉、MES 和多机器人扩展，但每项扩展有独立能力与验收门禁。

当前用户请求以完整方案为交付；本轮建立方案文件，不将未验证的整套新控制代码接入运行系统。后续可按阶段直接实施已授权的软件工作；硬件资料缺失只阻止依赖它的步骤，不阻止其余建设。

本方案新增文件之外，未修改运行源码、启动脚本、原始工程数据和现场审计。实施建议从M0基线与M1控制契约开始；夹爪/吸盘及手动切换是M3核心功能，不被推迟为仅可选的扩展。
