# 笛卡尔逆解与仿真停顿修复记录

本次针对反复“逆解未收敛”、残影无法加载、快速拖动覆盖目标，以及执行时逐段停顿。

## 已复现的原因

- 求解器将外部显示用的三位小数 FK 结果用于 0.001° 的数值微分，导致雅可比量化。已知可达目标 `[36.16276633,8.77385203,-4.10573759,90.08759884,-28.25831472,-83.53935888]` 的正解，从零位反解失败，残差约 2.59 mm / 2.31°。
- 纯牛顿方向线搜索失败后，没有继续尝试阻尼方向；伸直零位向下 5 mm 可达，但原算法停在零梯度。
- 笛卡尔拖动不使用上一组有效目标关节角，异步请求也缺少顺序校验；实际 TCP 快照会覆盖目标 TCP。
- 仿真 MOVEJ 复用了逐轴 MoveRelJ 兼容分段，并在每段末尾休眠 0.1 秒。

## 当前行为

- 从官方 URDF 层级计算几何雅可比，逆解内部 FK 保留完整精度；外部显示仍可取整。
- 牛顿方向失败后尝试阻尼方向，以有限的肘部、腕部初值重试处理奇异姿态。目标超出祖先链长度给出的保守半径时直接失败，避免无意义迭代。
- 恢复 0.05 mm / 0.05° 的分量残差阈值，不用放宽阈值掩盖错误。
- `/api/ik` 的 `seed` 指定初始关节角；`allow_partial` 仅用于滑块预览。失败时求解沿最后有效姿态到请求姿态的中间目标。返回 `clipped/fraction/requested/achieved`，明确区分请求和已求解目标；没有有效进度则保持上一组残影。
- 滑块只保留一条正在运行的逆解请求，后续输入合并，旧返回值不加载；求解中禁用执行。残影关节、目标 TCP 与正解一致。
- 关节点动、±、点位载入、模式切换统一刷新目标 FK，实际快照不覆盖残影目标。
- 仿真 MOVEJ 使用一条六轴同步轨迹和五次时间缩放，起终点速度、加速度平滑；耗时乘以 1.875，使峰值角速度不超过已配置上限。轨迹预检与仿真执行采用相同的同步关节路径。
- 滑块中间位置的求解失败显示在界面，不为每次拖动输出 interlock 审计日志。

## 验证

- `tools/check_cartesian.py`：11 项，包含已知可达姿态、零位回缩、连续轴拖动、边界退回、FK 对账、同步执行、速度上限、无内部停顿。
- `tools/check_cartesian_ui.mjs`：在独立且禁止真机连接的后端验证实际页面。残影可见、实际机器人不动；人为延迟旧逆解返回后，最新输入仍胜出；最多一条并发逆解；边界显示与残影 FK 一致；执行时多轴同步，轨迹中段无 100 ms 停顿；页面无运行错误。
- UI 证据：`output/cartesian-fix/ui-verification.json` 与 `verified.png`。
- 既有执行、功能、逆解、后端接口、正解对账检查通过后，在当前项目服务上只做无运动的逆解接口验证。

## 实际范围

这些是离线运动学与关节运动验证。笛卡尔页面生成末端目标并反解为关节目标，“执行目标”仍使用 MOVEJ；不能将它描述为保证 TCP 直线的 MOVEL。真机分段兼容通道未修改，控制器真实加速度、插补、标定工具和负载尚未现场校准。数值残差阈值不代表真机定位精度。

资料核对：[华沿官方 API](https://github.com/huayan-robotics/elfin_f_robot/blob/main/docs/API_description_english.md) 区分关节目标、笛卡尔目标和直线路径；[MoveIt pick_ik 文档](https://moveit.picknik.ai/main/doc/how_to_guides/pick_ik/pick_ik_tutorial.html) 建议相对移动、末端点动从局部初值求解。
