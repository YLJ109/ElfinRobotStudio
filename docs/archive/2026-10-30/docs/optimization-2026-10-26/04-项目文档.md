## 项目范围与约束

清晰易用的机器人仿真与监控工作台；先稳定核心，再完成仅仿真的手势跟随。用户离场时不触碰实机。

- 项目形态：web-3d
- 包管理器：npm
- 所选脚手架：Three.js + Vite + TypeScript；已有项目沿用已验证技术栈。
- JSON 方案描述业务；基础脚手架不能自动实现页面、接口、数据模型或权限。

## 架构概览

保留现有模块化单体：FastAPI World为状态源，Vue/Pinia显示状态，Three.js负责视觉；相机采集与MediaPipe Worker独立。新增手势用例与真实命令适配器物理隔离，不能复用可能按mode路由到真机的moveJ调用。

| 组件 | 职责 |
| --- | --- |
| World/RealLink | 真实状态质量、电源序列、代次与执行撤销；取消保电严格确认disabled。 |
| CameraManager | 支持的profile、共享最新JPEG、MJPEG、真实采集帧率、session/过期限制与按需点云。 |
| CameraWidget/CameraFrame/Worker | 日志同主题小卡片、镜像叠层、本地食指、检测限频与生命周期。 |
| Three.js scene | 官方模型、皮肤与黑色面片、可见围栏、残影、视角持久化；不直接控制设备。 |
| 未来SimHandFollow | 归一化映射、滤波、相对尺度与角度、IK与盒内逐帧检查，仅能调用虚拟状态。 |

## 架构决策

### ADR-001 · accepted

- 背景：用户要求简洁核心页但保留故障诊断
- 决策：摘要状态与核心动作常驻，技术细节放诊断tab/折叠详情，精简提示而非吞错误
- 后果与代价：布局、错误组件和日志去重一起改；不用UI隐藏代替后端保护
- 来源：项目判断

备选方案：
- 删除所有提示会隐藏危险状态
- 所有诊断堆主页面会挤占操作

### ADR-002 · proposed

- 背景：普通RGB只有手关键点，用户希望前后/旋转跟随
- 决策：先平面映射，前后基于校准手掌尺度相对估计，旋转先屏幕角；准确深度/6D需后续深度/标定
- 后果与代价：界面明确相对估计，IK不收敛保持最后有效目标；不能保证整个任意盒子都可达
- 来源：SRC-002

备选方案：
- 声称单指精确6D不可验证
- 直接真机跟随超出本轮授权

### ADR-003 · accepted

- 背景：已有完整工作站与旧方案，用户要求先方案同时小修
- 决策：增量计划并复用现有框架，简单明确问题继续；复杂手势/页面重构先规格
- 后果与代价：保留dirty变化和旧资料，以本计划的最新需求为准
- 来源：项目判断

备选方案：
- 全仓重写成本和回归风险高
- 只写空泛方案不继续小修不符合用户最新指令
