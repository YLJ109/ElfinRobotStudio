# 全面翻新与企业化重构设计

日期：2026-10-30。状态：**实施中，尚未全面验收**。方案活源：project.json中的enterprise_renewal_20261030。已落地与未验以STATUS及证据为准；下面目标设计不自动等于已实现。这里的“企业化”指明确责任、契约、可复现验证与恢复，不是商标背书或安全认证。

## 1. 目标、现状与路线

全面翻新代码职责、目录结构、交互与交付方式，目标是可维护、可观察、可验证和可恢复，不承诺零缺陷或未经认证的企业/安全等级。

前一轮只交付文档与方案；本轮已按用户新授权实施源码、隔离测试、仿真、浏览器和本地构建。真实机器人/IO/相机、外部AI、数据外发及发布仍禁止。

保留Windows+FastAPI+Vue+Three.js+Electron，采用模块化单体、端口/适配器与渐进替换。先修已知行为缺陷，再沿完整用户路径抽离；不通过一次搬目录制造全面重构完成的假象。

当前热点：World承担路由编排外的大量运动/工具/任务/状态；main导入即构造运行对象；前端App/store/scene耦合生命周期；staged副本与正式检查混用；同参数多入口、模式/反馈口径和实际效果不一致。必须先修行为，再抽边界，不用目录美化替代缺陷关闭。

## 3. 拟议目录与依赖方向

以下均为目标路径，不是现有文件清单。

```text
backend/
  main.py                 # 现有ASGI兼容入口
  bootstrap.py            # 显式依赖组装与生命周期（拟议）
  api/                    # HTTP/WS与DTO，不拼设备报文
  application/            # motion/interaction/tasks/vision/ai/tools/scene用例
  domain/                 # 无I/O的规则、状态/计划与几何
  infrastructure/         # devices/huayan、simulation、vision、persistence
web/src/
  app/                    # 应用壳、导航、组装
  features/               # 按用户业务收拢组件和状态
  graphics/               # renderer、assets、materials、camera、资源释放
  shared/                 # 真实共用UI/SVG/请求，不是万能业务桶
contracts/                # 拟议共享Schema与生成规则
tests/                    # 拟议unit/integration/contract/e2e/hardware
desktop/                  # 保留桌面进程监管边界
tools/                    # 保留兼容入口，工具按用途渐进收拢
docs/                     # 当前文档、方案和隔离归档
```

| 目标 | 职责 |
| --- | --- |
| backend/main.py | 保留ASGI兼容入口，组装移到bootstrap/app factory，导入不隐式启动设备。 |
| backend/api/ | HTTP/WebSocket路由、协议DTO、鉴权与能力投影；不直接驱动硬件。 |
| backend/application/ | motion、interaction、tasks、vision、ai、tools、scene用例编排与状态机；唯一运动所有权。 |
| backend/domain/ | 坐标/运动学/计划/工具/任务规则等可纯测逻辑，无网络、磁盘或UI依赖。 |
| backend/infrastructure/ | huayan设备传输、仿真、采集/推理、持久化与日志适配；生命周期由bootstrap控制。 |
| web/src/app/ | 页面壳、导航、依赖组装与全局状态，保持页面不直接拼设备命令。 |
| web/src/features/ | teaching、interaction、tasks、vision、scene、program、ai、system按业务聚合组件与状态。 |
| web/src/graphics/ | 三维渲染、资产加载、材质、相机与资源所有权，不维护另一份执行状态。 |
| web/src/shared/ | 有真实复用的UI/SVG/请求/格式化，不塞业务控制为万能utils。 |
| contracts/ | 后续建立版本化快照、任务/动作与错误Schema，明确唯一源及生成关系，不手工维护冲突副本。 |
| tests/ | 后续按unit/integration/contract/e2e/hardware分层；现有tools/web scripts原入口保留到迁移验收。 |
| desktop/; tools/; docs/ | 桌面进程监管；受控命令/测试工具；精简活跃文档+可恢复归档。运行数据和模型不当源码垃圾清除。 |

依赖方向：UI/API→application→domain；infrastructure实现application定义的端口，bootstrap注入。domain不反向导入World/路由/存储/设备；设备层不直接改页面状态。按实际职责拆包，文件规模不是唯一拆分理由。

## 4. 模块契约与数据

| 契约 | 至少包含 | 不得混淆 |
| --- | --- | --- |
| RobotSnapshot | 单调采集时间/帧号、连接身份、有效性、关节/PCS参考系、使能/错误来源 | 收到时间不能续期旧采集；未知不是0 |
| MotionPlan | plan ID、起点证据、目标/裁剪结果、IK分支、方式、工具/UCS/场景/限位修订 | 终点残影不是路径预测；ACK不是到达 |
| OperationToken | 请求ID、任务/所有者、代次、取消状态、期限 | UI重新进入不恢复旧许可 |
| ToolProfile | 实际安装、TCP、负载、包络、IO/气路及资格适用条件 | 外观不是实际工具；8动作不是8输出 |
| VisionResult | 图像源/会话、采集时间、类别/置信度、标定与估计边界 | 仿真代理/指定高度不当真实测量 |
| TaskRun | 配方/程序版本、步骤、部分完成、持件、停止与恢复 | 准备完成/已提交/已执行分别处理 |
| Capability/Error | 适用模式/设备版本、当前可用原因、错误码、可恢复性和来源 | 协议收录不当软件接入或现场资格 |

位置mm、角度degree、旋转组合/基座/用户/法兰/参考点/工具TCP必须显式；时间期限用单调时钟，墙钟仅用于日志展示。数据与合同版本有迁移策略，不使用不受控的任意字典承载关键设备命令。

## 5. 运行与控制设计

- 运动与危险工具输出共用唯一所有权和后端联锁；正常查询/心跳不能绕开独占事务。
- 停止优先撤销新目标，再证明原会话静止；失败保留隔离。网络重连不重放旧运动，空闲可恢复也需明确状态。
- 有限MOVEJ、原生MOVEL和Servo独立适配及资格；兼容路径明确标签，不因新接口不可用静默降级。
- 仿真与真机共享任务语义，不假设动力学/轨迹相同；真机验证按CART/REAL专项。
- 配置按影响域分修订：视觉/布局与安全/工具分别失效，不能改透明度就意外终止作业，也不能安全变化仍沿旧计划。
- 采集/检测/显示独立worker和最新帧槽；CPU重任务/模型加载不占控制事件循环。设备热插拔、失败和取消由生命周期统一处理。
- 计划解析/编译是确定性边界；AI只有候选，输入来源标识和权限不由模型授予。

## 6. 前端、场景与资产设计

当前任务是主线，导航不再按模块数量无限增长。合并相同参数/效果的入口，保留职责不同的标定和必要停止。桌面专用能力按运行环境投影，不留浏览器死按钮。
场景稳定ID绑定外观、任务物料与碰撞代理；名称编辑草稿独立。资源单位、实际尺寸、导入预算与包内路径检查按APP-001执行。
图形层只展示真值与预览，不能维护第二份执行结果。统一SVG/token/页签/浮层；125%至200%缩放和键盘路径验收。
三维按需渲染并处理持续动画/相机消费者，初始化/失败/取消都有资源释放。CPU耗时、GPU耗时和最终帧间隔分开。

## 8. 每次抽离的实施模板

1. 从一条现有用户路径选切片，记录当前参数/状态/错误和外部契约。
2. 建失败复现和行为特征测试，在隔离副本固定旧基线，不修改真实运行数据。
3. 抽端口/纯规则，原入口用显式薄门面适配；新旧实现不能同时持有硬件控制权。
4. 对同输入比较结果与副作用；如预期行为变更，记录理由/迁移，不强迫旧错误继续通过。
5. 修导入/资源/打包/测试/文档引用，保持start.bat和现有ASGI兼容直到替代入口验收。
6. 定向及相邻回归、必要UI/GPU检查后再合并，保留回退位置；业务代码回退前检查数据兼容。
7. 删除确认无人调用且无兼容责任的旧实现，不做永久双引擎回退，不把临时facade永远当完成。

上述步骤现已开始执行，逐包实际完成及缺口见STATUS与project.json；隔离仿真与本地构建授权不扩展为现场运动或真实数据迁移。

## 9. 数据、发布与供应链

运行数据与代码/缓存/模型/证据分开。备份→新目录恢复演练→迁移预览→原子提交→失败恢复；稳定ID与旧文件版本兼容。资格与设备/固件/工具绑定，配置导入不授予资格。
依赖使用锁定与兼容矩阵；可选视觉/AI按需安装，首屏不等待大模型。模型/数据集/图标/第三方资源分别记录来源、许可与版本，导出ONNX不移除原许可义务。
开发与稳定发布分开：产物核对指纹、入口、无开发端口依赖、用户数据路径、敏感信息与卸载/升级行为。签名、安装器和恢复演练未做不能宣称企业发布完成。

## 10. 测试、故障与性能验收

- 逐文件语法/导入/资源引用与API契约校验；变更风险决定测试范围，不用测试总数代替效果。
- critical路径的权限/停止/过期/旧连接/并发/部分完成有负例；CI禁止硬件和不可信网络访问。
- 代表流程：离线启动→摆放/改名→识别→生成→预检→确认→执行→取消/恢复→保存重开。计划未实现阶段只做相应离线测试。
- 备份→迁移→失败恢复演练，兼容旧场景/点位/程序/工具，不清数据解决问题。
- 同设备综合负载：3D+相机+推理+日志+任务，统计帧龄/事件循环/内存/调度，保护优先于画质。
- 开发与稳定发布入口分离，产物包含版本/契约/模型指纹/依赖和许可清单；不依赖开发端口发布。
- 现场验证先只读再按明确授权逐层推进，不自动使能、试IO或启动运动。

测试分层：纯规则unit→假适配integration→API/WS/Schema contract→用户路径e2e→真机只读/有限/连续分级。硬件测试不在普通CI执行。错误包括部分帧/粘包、迟到ACK、旧连接、推理超时、模型损坏、磁盘写失败、断电/断网后的未知状态；不将软件假故障注入当物理验证。
性能先同设备基线，报告分布/尾延迟与峰值资源；不编造30fps、控制周期或停机距离保证。超期保护/停止不得因视觉负载饿死。无小时级长测不称长期稳定。

## 14. 摄像头：默认直接预览，检测统一由工作站处理

“本地”指运行后端的工作站，而非任意访问者的电脑。用户确认两类入口均需兼容；最后补充为：**未开启检测时默认前端直接预览，开启检测后由工作站处理结果再发送。** 不是检测失败时静默切换并继续显示成功。

| 情况 | 采集和处理 | 页面接收 |
| --- | --- | --- |
| 普通预览，不检测 | 浏览器getUserMedia→本地video，不上传 | 本机原画面；不启动推理、不启动跟随 |
| 工作站本地相机检测 | 后端采集一次→最新原始帧→后端统一检测 | 工作站页面按需预览流+结构化结果，不上传同一画面绕行 |
| 手机/远程电脑相机检测 | 浏览器授权采集→上传至工作站→统一检测 | 手机保留本机预览并接收结果；主工作台按需订阅画面，不向手机重复回传自身视频 |
| 前端仿真相机 | Three.js本地渲染；检测需要时才提交帧 | 本地预览优先，不为统一路径造第二套后端渲染器 |

当前实际：backend/core/cameras.py已经后端采集本地真实相机；backend/main.py输出MJPEG；CameraFrame.vue接收JPEG并由前端Worker检测手掌，再发布关键点。不能误写成真实视频本来就在前端采集后完整往返。统一后端手掌检测、手机上传、模式切换尚待开发。

### 14.1 统一服务，不重复功能

FrameSource适配本地、远程、仿真来源，输出统一帧元数据；同源只采集一次，检测服务不重复运行前后端推理。原始帧供检测，预览按消费者需求编码；检测结果和视频分通道传输，结果无需等待下一张预览。队列有界，忙时丢弃中间帧、处理最新帧。

本地保留MJPEG作为兼容基线并先测编码/解码成本；手机优先评估WebRTC，要求实现信令、接收端、认证和限流，不把一条浏览器API当作已接入。禁止默认逐帧Base64上传再把相同画面回传。临时JPEG上传若用于原型必须标明实验路径、限制频率/分辨率，并给退出条件。

### 14.2 切换、断流和控制边界

切换流程：准备目标源→释放旧占用→接管→收到首个有效新帧→激活。浏览器与后端不得同时抢同一设备；失败需清楚显示权限拒绝/占用/未连接/推理失败，可恢复普通预览但不能宣称检测运行。检测和真机跟随独立启停，换源撤销旧目标，不自动恢复旧运动许可。

结果携带source/session/epoch/frameSeq、采集/接收/推理时间、模型版本、有效性和坐标系。跨手机与工作站的单调时钟不可直接相减，需估计时钟映射与不确定性；页面展示保留不延长运动结果有效期。分开统计采集、检测、显示帧率和帧龄，30fps为待验证目标，不能设参数后就当已达到。

手机权限与HTTPS不能省略；普通局域网HTTP不能当成可用方案。需要配对、令牌、撤销、来源校验、大小/带宽预算、超时与页面退出释放；默认不开放互联网和自动录像。参考：[浏览器采集与权限](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[WebRTC标准](https://www.w3.org/TR/webrtc/)，核对日2026-10-30。网络来源视频/识别结果仍是不可信输入，不授予机器人权限。

### 14.3 实施映射与验收

并入REN-02/03/06/07/08，不另造一套相机任务引擎。先单源+统一结果，再双入口和切换，最后综合性能及多端验证。验收：不检测零帧上传/零推理；本地检测一次打开；手机不回传重复视频；权限拒绝、设备占用、锁屏、断网、切源、退出都不复活旧目标；3D+识别+日志综合负载报告P95延迟、帧龄、CPU/GPU/内存/带宽，不削减保护换帧率。
