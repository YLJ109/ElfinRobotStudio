# 用户文档

读法：现有行为有源码支持，不代表本轮已进行界面或现场验收；“计划”内容不写成已存在的操作步骤。

## 当前可以做什么

| 页面/功能 | 当前用途 | 注意 |
| --- | --- | --- |
| 总览/驱动 | 查看状态、连接与就绪入口 | 缓存状态存在已知问题，真机以有效回读和现场保护为准 |
| 点位 | 关节/笛卡尔目标预览、保存与明确执行 | 笛卡尔输入不是保证直线；自动姿态仅离线仿真 |
| 功能/交互 | 手掌、鼠标、键盘、手柄输入 | 非所有输入都具备真机资格；跟随已知缺陷待修 |
| 功能/井字棋 | 仿真机器人为双方落子 | 随机先手，O先行，执行后才轮到下一步 |
| 功能/分拣 | 仿真视觉取放与程序预检 | 需要有效识别和标定；两个预检参数源待合并 |
| 场景 | 添加预设、属性/坐标轴编辑、JSON现场保存载入 | 名称草稿和唯一性待修；网格导入是计划 |
| 视觉 | 选来源、预览、颜色/轮廓识别、平面标定 | 有效相机/图像来源清楚，代理高度不是测得深度 |
| 工艺/程序 | 录制/草稿/解析/预检与执行 | 复制、载入编辑器、预检和执行是不同动作 |
| AI | 聊天调用、规则整理和本地辅助 | 配置不等于模型可用，聊天不掌握完整现场状态 |
| 系统 | 工具、IO、日志、遥测、设置 | 若显示已保存但未生效，按已知问题处理，不反复点 |

## 点位与残影

1. 选择目标来源，编辑关节或XYZ/姿态。
2. 等待有效求解与后端确认，核对残影和预检结果。
3. 只有明确执行才运动；求解失败不能把旧残影当新目标。
4. 仅查看点位时不应自动收残影；执行后达到正确反馈与停稳条件才确认。
5. 真机逐轴兼容路径与仿真同步路径不同；此差异尚待CART专项统一表达，不能根据终点残影猜中途路径。

## 场景与名称

当前物体库选类型添加，可打开移动轴拖动，松开提交；JSON保存/载入会改变现场，先确认已有物体与任务。
名称可提交修改，但目前缺独立草稿/同场景唯一性，出现覆盖或失败保留现场记录，不误认为本轮已修。
规划目标是：同场景名称唯一、稳定ID不变、复制建议编号、编辑不被刷新覆盖、失败保留草稿。

## 井字棋与分拣

井字棋先布置5O4X，启动对局随机分配O/X，O先走。用户选格后等待机器人完成，不能忙时连点。离页可能取消对局；已知提示待完善，查看诊断前核对当前任务。
分拣先布置乱序物料，采集A区并完成识别/标定，再生成、预检和确认。确认所用速度/高度/等待位，当前重复预检按钮参数源不一致。
“普通场景整理”只改变普通物体位置，与机器人取放不同。重置物料回A不是机器人把物体搬回。

## 相机与识别

刷新列表不等于开启；选择来源和开启是不同操作。仿真相机与真实设备不能混为一谈。
浏览器独立视觉窗口按钮有已知能力判断问题；浏览器用内嵌页，桌面有对应窗口能力时再用。
现有识别是颜色/轮廓；未标定显示像素。平面坐标依赖当前相机会话/视角，改变成像或相机位置需重新核对；不声称已经完成真实手眼标定。

## AI使用

明确点位、速度、等待等走本地白名单整理；开放问题有真实模型调用代码。状态诊断和草稿差异是本地工具，不是假装模型推理。
先看回答来源、缺少的信息与实际计划。确认执行前核对工具、IO、路径和当前环境；历史回答和模型建议不授予执行许可。
AI不能凭当前聊天自动修复源码、猜接线或启动真机。响应异常或无上下文应显示不能判断，详见AIQ/TRUTH问题。

## 计划中而非现成功能

左右吸盘八项专用控制、广格式模型导入/缩放预算、YOLO CPU、搬运闯关/找物/缺件/装盒/拼摆、统一SVG及新恢复界面。
首批优先场景沙盒、分拣挑战、井字棋完善、搬运闯关。已存在能力先复用，不另建重复执行链。

## 遇到问题

停止反馈未知时保持闭锁，不用重复启动“试试看”；记录时间、模式、操作、错误与计划ID，不发送凭据。
不要用强制刷新、关闭服务或释放吸盘代替安全停止。恢复策略见[操作指南](ROBOT_OPERATIONS.md)和[运维](OPERATIONS.md)。
